## Setup

Nothing under `data/` or `artifacts/models/` is in version control — it is either
downloaded (684 MB of raw CSVs) or regenerated by the scripts (~460 MB). A fresh
clone therefore needs three steps before anything will run.

**1. Environment.** Python 3.10 or 3.11; TensorFlow 2.13 has no wheels for 3.12+.

```powershell
py -3.10 -m venv ..\.venv
..\.venv\Scripts\Activate.ps1
pip install -r ..\requirements.txt
```

TensorFlow 2.13 is CPU-only on native Windows (GPU support ended at 2.10). The
models here are small enough that this costs minutes, not hours.

**2. Download the raw data** into `data/raw/`. Two files from the CSE-CIC-IDS2018
public bucket, 717 MB total, no AWS account needed. **The bucket lives in
`ca-central-1`** — it used to be `eu-west-3`, and that endpoint now answers 301
`PermanentRedirect`:

```powershell
aws s3 cp --no-sign-request --region ca-central-1 `
  "s3://cse-cic-ids2018/Processed Traffic Data for ML Algorithms/Friday-16-02-2018_TrafficForML_CICFlowMeter.csv" data\raw\
aws s3 cp --no-sign-request --region ca-central-1 `
  "s3://cse-cic-ids2018/Processed Traffic Data for ML Algorithms/Friday-23-02-2018_TrafficForML_CICFlowMeter.csv" data\raw\
```

No AWS CLI needed — the objects are public over plain HTTPS, and `-C -` resumes a
dropped transfer rather than restarting 380 MB:

```powershell
$b = "https://cse-cic-ids2018.s3.ca-central-1.amazonaws.com/Processed%20Traffic%20Data%20for%20ML%20Algorithms"
foreach ($f in "Friday-16-02-2018_TrafficForML_CICFlowMeter.csv",
               "Friday-23-02-2018_TrafficForML_CICFlowMeter.csv") {
  curl.exe -L --fail --retry 5 -C - -o "data\raw\$f" "$b/$f"
}
```

Expected sizes: `02-16` is 333,723,605 bytes and `02-23` is 382,840,456 bytes. The
same files are also on Kaggle (`solarmainframe/ids-intrusion-csv`); keep the
filenames exactly as above either way, since `config/data.yaml` refers to them by
name.

**3. Rebuild the ignored artefacts** by running the phases in order. Everything is
seeded (`seed: 42`), so you get identical splits and the same tables.

| Step | Command | Produces | Time |
| --- | --- | --- | ---: |
| Verify setup | `python scripts\01_prepare.py --sample-frac 0.02` | throwaway smoke test | ~50 s |
| Phase 1 | `python scripts\01_prepare.py` | `data/interim/`, `data/processed/` | ~2 min |
| Phase 1b *(optional)* | `python scripts\01_prepare.py --no-dedup --out-dir data/processed_paperparity --tag paperparity` | `data/processed_paperparity/` | ~1 min |
| Phase 2 | `python scripts\02_train_baselines.py` | `artifacts/models/*.keras` | ~2.8 h CPU |

Run the smoke test first — it exercises the whole pipeline in under a minute and
fails loudly if the CSVs are missing or truncated.

Phase 2 is the long pole: MLP ~3 min, CNN ~42 min, LSTM ~2 h on CPU. Use
`--models mlp` to train just one, or `--epochs 5` for a quick end-to-end check.

The `artifacts/reports/` tables **are** committed, so you can compare your run
against the reference numbers without regenerating anything.

## Phase 2 — baseline NIDS

```powershell

```

All three take a flat `(68,)` input and emit a 2-unit softmax under

## Phase 3 — AE generator

```powershell
python scripts\03_generate_ae.py --models mlp --attacks fgsm --n-samples 50 --no-sweep   # smoke test
python scripts\03_generate_ae.py                                                          # full run
```

Wraps each Keras model in ART's `TensorFlowV2Classifier` and runs four white-box
evasion attacks against it, producing 4 attacks x 3 models x 5,000 = **60,000
adversarial samples**. Threat model: white-box, evasion, non-targeted.

| Path | Contents |
| --- | --- |
| `artifacts/adversarial/{attack}_{model}.npz` | 12 files: `X_adv`, `X_clean`, `idx`, labels, before/after predictions, perturbation norms, JSON `meta` |
| `artifacts/reports/table4_evasion.{csv,md}` | Table IV — evasion per (model, attack) |
| `artifacts/reports/eps_sweep.csv` | accuracy-vs-eps curve |
| `artifacts/reports/figures/fig{3,4}_*.png` | Figures 3 and 4 |

Every knob lives in `config/attacks.yaml`.

Four decisions that determine whether the numbers mean anything:

- **One fixed set of 5,000 source rows, shared by all twelve cells.** Seeded, drawn
  only from `y == 1` test rows. Same rows everywhere is what makes the twelve
  results comparable, lets phase 5 pair each adversarial row with its exact clean
  original, and lets phase 4 score catch-rate against an identical clean baseline.
- **The true label is passed to `generate()`.** With `y=None` ART substitutes the
  model's own prediction, which makes the result depend on model error and quietly
  changes what "evasion" means.
- **DeepFool is excluded from the eps sweep.** Its `epsilon` is an *overshoot
  multiplier*, not an L-inf budget — sweeping it produces a curve that looks
  meaningful and is not. `build_attack()` raises if you try. Its ART defaults also
  need overriding: `batch_size=1` (would be 5,000 sequential passes) and
  `nb_grads=10` (we have 2 classes).
- **DeepFool  iruns against a logits view of the model**, the other three against the
  softmax. DeepFool navigates distances to the decision boundary, which softmax
  compresses; ART warns about it, and it is not cosmetic. On a smoke fixture the
  fix cut DeepFool's mean L2 perturbation against the MLP from 3.77 to 0.85 for the
  same 100% evasion. `as_logits()` shares the trained weights and changes no
  prediction — softmax is monotone, so `argmax` is identical.
- **Both the clean and the perturbed prediction are stored**, so evasion can be
  measured over the rows the model actually got right.

Resumable: a cell whose `.npz` exists is skipped unless `--force`. Two assertions
fail the run loudly if adversarial rows escape `[0,1]` or exceed their eps budget —
both would invalidate every downstream phase while still writing plausible files.

**Sample composition caveat.** The test split holds 21,870 attack rows, 21,780 of
them DoS-Hulk; the web-attack classes have 7–51 rows each. The 5,000 source rows
are therefore ~99.6% Hulk, and stratifying across attack types is not possible at
this scale. State it rather than paper over it.

## Phase 4 — inbound analyzer + validator

```powershell
python scripts\04_analyze_validate.py
```

Mines benign **training** flows into `artifacts/rules.json`, then measures the gate
on data it never saw.

| Family | Rule | Mined from |
| --- | --- | --- |
| Range | per-feature `[min, max]`, padded 1% of span | benign train |
| Integrality | count-like columns must be whole numbers | discovered empirically, not hardcoded |
| Dependency | 14 arithmetic invariants (ordering, product, rate) | tolerance = 99.9th pct of benign residual |
| Distribution | robust median/MAD z-score | threshold calibrated on benign **val** at a 1% FPR budget |

- Checks run in **raw units**, not scaled space — "whole number" becomes "on a
  lattice of step `1/(max-min)`" after MinMax. `data_min`/`data_range` are copied
  into `rules.json`, so the validator is pure numpy with no sklearn at inference.
- The residual arithmetic lives in `validator.py` and `analyzer.py` **imports it**
  to calibrate. Two copies could drift, and every tolerance would then gate
  something other than what it was calibrated on.
- Mine on train, calibrate on val, report on test. Calibrating the distribution
  threshold on the rows it was mined from reports an optimistic FPR — the exact
  leak this project criticises elsewhere.

`artifacts/reports/table5_validator.{csv,md}` reports **catch-rate and FPR
separately, per rule family**. A gate rejecting 3% of legitimate traffic is
unusable whatever it catches, and per-family attribution is what tells you whether
the defense rests on arithmetic (which an adaptive attacker can satisfy) or on
distribution.

**Do not quote the raw catch rate.** Every adversarial row is built from a real
attack flow, and real attack flows already fall outside the benign envelope the
rules were mined from — so the gate rejects a large share of *clean, unperturbed*
attack rows too. A headline catch rate therefore partly measures maliciousness
rather than perturbation. The table carries `clean_orig_%` (the same rows
unperturbed) and `attributable_%` (rejected only after perturbation) beside it;
`attributable_%` is what the gate actually contributes as an AE detector. This is
why phase 3 stores `X_clean` in every `.npz`.

Expect integrality alone to carry most of the catch rate. That is the honest
finding: gradient attacks violate it *incidentally*, not because they are forced
to. An adversary that rounds onto the integer lattice and re-derives the dependent
features walks through untouched — which is what phase 8 exists to demonstrate.

## Phase 5 — adversarial discriminator

```powershell
python scripts\05_train_discriminator.py
```

Gate 2: a Random Forest (Gini, 200 trees) over the same 68 features, trained to
separate clean flows from perturbed ones. 120,000 rows — the 60,000 adversarial
rows from phase 3 against 60,000 clean ones. ~40 s for all eight fits.

The task is easy to score well on and hard to score *honestly* on, so three
shortcuts are closed by construction:

| Shortcut | How the forest could exploit it | What closes it |
| --- | --- | --- |
| The paired twin | every positive has a clean original differing by L2 ≈ 0.03–0.7; split randomly and its twin is in training | every split is **grouped on the source flow** — all 13 rows from one flow move together |
| Maliciousness | all positives are perturbed *attacks*; with benign-only negatives, "is this malicious" separates the classes perfectly | the 5,000 exact clean twins are always negatives |
| Attack family | FGSM/BIM/PGD are all signed-gradient and leave near-identical traces | `leave_one_attack_out` withholds a whole family from training |

### Table VI — the gap is the result

| Protocol | Held out | Catch % | FPR % |
| --- | --- | ---: | ---: |
| random | – | **100.000** | 0.000 |
| leave-one-attack-out | bim | 100.000 | 0.000 |
| leave-one-attack-out | **deepfool** | **2.853** | 0.000 |
| leave-one-attack-out | fgsm | 100.000 | 0.000 |
| leave-one-attack-out | pgd | 100.000 | 0.000 |
| leave-one-model-out | **cnn** | **14.100** | 0.000 |
| leave-one-model-out | lstm | 99.882 | 0.000 |
| leave-one-model-out | mlp | 99.966 | 0.000 |

The paper's protocol is the first row, and it reproduces at 100% with zero false
positives. Withhold DeepFool from training and the same forest catches **2.85%**
of it — a **97-point** generalisation gap. BIM, FGSM and PGD hold out perfectly
because they are the same attack at different iteration counts: training on any
two covers the third. DeepFool is a different algorithm producing a perturbation
16× smaller, and nothing the forest learned from gradient-sign attacks transfers
to it.

Leave-one-model-out shows the same failure along the other axis: hold out
everything crafted against the CNN and the catch rate falls to 14.1%. The CNN's
global max-pooling makes its gradient sparse — its perturbations touch ~21 of 68
features against ~45 for the others — so the fingerprint the forest learned from
MLP and LSTM examples simply is not there.

### The two gates are not independent

**9 of the forest's top 15 features are columns the phase-4 validator already
checks for whole-numberedness** (0.469 of the total Gini importance mass). The
discriminator has largely rediscovered the validator's arithmetic rather than
adding a separate obstacle. Phase 7 must not treat their catch rates as
multiplying, and a single adaptive attacker who rounds onto the integer lattice
degrades both at once.

Reported in `artifacts/reports/table6_discriminator.{csv,md}`, with the
deployable forest at `artifacts/discriminator/rf.joblib`.

## Phase 6 — EIDS: adversarial training + OR ensemble

```powershell
python scripts\03_generate_ae.py --split train --n-samples 10000 --attacks fgsm bim pgd
python scripts\06_train_eids.py
```

Phases 4 and 5 are gates *in front of* an unchanged NIDS. This is the only phase
that changes the models. Two mechanisms: retrain each architecture on the clean
training set plus adversarial examples labelled attack, then take the verdict as
`MLP ∨ CNN ∨ LSTM`.

Two disciplines are wired in because both are easy to get wrong in a flattering
direction:

- **The training examples come from the training split.** `--split train` writes
  to `artifacts/adversarial_train/`; the test-derived set in
  `artifacts/adversarial/` is never touched. Augmentation is 1,047,517 clean +
  90,000 adversarial (+8.6%). Validation stays clean — early stopping on a mixed
  set would trade away accuracy on the traffic that is 100% of normal operation.
- **DeepFool is withheld from training entirely.** Phase 5 showed why: a held-out
  PGD is caught 100%, a held-out DeepFool 2.85%. Holding out any gradient-sign
  family leaves the other two to cover it.

Training: MLP 110 s, CNN 59 min, LSTM 31 min. Adaptive evaluation ~14 min.

| MLP | eids | 99.9898 | 99.9131 | 0.0020 | 19 | 4 |
| CNN | baseline | 99.9791 | 99.8080 | 0.0025 | 42 | 5 |
| CNN | eids | 99.9728 | 99.7348 | 0.0015 | 58 | 3 |

Hardening cost nothing in ensemble recall and *reduced* its false-alarm rate.
The hardened MLP makes byte-identical clean predictions to the baseline despite
weights differing by up to 1.6 — a genuinely different model that happens to fail
on the same 19 rows.

### The LSTM is pure cost in the ensemble

Counting rows only one member flags, split by ground truth:

| | unique catches | unique false alarms |
| --- | ---: | ---: |
| MLP | 24 → 40 | 2 → 2 |
| CNN | 1 → 1 | 2 → 0 |
| **LSTM** | **0 → 0** | **541 → 429** |

The LSTM never catches an attack the other two miss, and it contributes 541 of
the ensemble's 548 false positives. Under OR a member can only add — a lone flag
is passed through whether the row is an attack or not — so a member with zero
unique catches is a false-positive generator and nothing else. Measured directly:

| ensemble | recall | FPR | fn | fp |
| --- | ---: | ---: | ---: | ---: |
| MLP ∨ CNN ∨ LSTM | 99.9177% | 0.2705% | 18 | 548 |
| MLP ∨ CNN | 99.9177% | **0.0035%** | 18 | **7** |

Identical recall, a **78× lower** false-alarm rate.

This is worth stating against the paper, which combines all three by design. The
combination is only justified if every member covers something the others miss,
and on this data one of the three does not.

### The rare-class regression

| class | support | MLP eids | CNN base → eids | LSTM base → eids | OR hardened |
| --- | ---: | ---: | ---: | ---: | ---: |
| Type1 DoS-Hulk | 21,780 | 99.995 | 100 → 100 | 99.775 → 99.908 | 100 |
| Type2 DoS-SlowHTTPTest | 9 | 100 | 100 → **0** | 100 → **0** | 100 |
| Type3 BruteForce-Web | 51 | 66.667 | 49.02 → **37.26** | 0 → 0 | 66.667 |
| Type4 BruteForce-XSS | 23 | 95.652 | 39.13 → 39.13 | 0 → 0 | 95.652 |
| Type5 SQL-Injection | 7 | 100 | 71.43 → **57.14** | 0 → 0 | 100 |

Adversarial training made rare-class detection **worse** for the CNN and LSTM —
capacity spent on 90,000 perturbed DoS-Hulk flows is capacity taken from classes
holding 7 to 51 rows. The OR ensemble hides it completely, and it hides it for
one reason: the MLP carries every rare class on its own. Remove the MLP and the
EIDS detects no web attacks at all.

### Table VIII — robustness, two regimes

**Transferred** (phase 3's saved examples, built against the *baseline* weights,
replayed at the hardened models) is ~100% in all 12 cells, up from 0–0.6%. Even
the held-out DeepFool is caught at 99.5–100%, so this regime is not measuring
attack-specific learning — it is measuring that the weights moved.

**Adaptive** (each attack recomputed against the *hardened* weights, on the same
5,000 source rows Table IV used) is the honest number:

| crafted against | attack | that model holds | MLP | CNN | LSTM | **ENSEMBLE** |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| MLP (hardened) | FGSM | 0.00 | – | 72.26 | 6.14 | **73.36** |
| MLP (hardened) | BIM | 0.00 | – | 89.72 | 16.68 | 99.44 |
| MLP (hardened) | PGD | 0.00 | – | 89.62 | 13.22 | 95.90 |
| MLP (hardened) | DeepFool | 5.94 | – | 99.78 | 99.36 | 99.80 |
| CNN (hardened) | FGSM | 89.38 | 99.86 | – | 98.28 | 99.90 |
| CNN (hardened) | BIM | 81.84 | 30.48 | – | 84.72 | 99.36 |
| CNN (hardened) | PGD | 72.44 | 22.92 | – | 90.98 | 98.24 |
| CNN (hardened) | DeepFool | 12.84 | 99.76 | – | 89.40 | 100.00 |
| LSTM (hardened) | FGSM | 0.00 | 100.00 | 96.84 | – | 100.00 |
| LSTM (hardened) | BIM | 0.00 | 100.00 | 95.94 | – | 100.00 |
| LSTM (hardened) | PGD | 0.00 | 100.00 | 99.94 | – | 100.00 |
| LSTM (hardened) | DeepFool | 4.08 | 100.00 | 99.82 | – | 100.00 |

**Adversarial training did not make the individual models robust.** The hardened
MLP and LSTM still fall to 0.00% against a fresh white-box attack on their own
weights. Only the CNN retains anything (72–89% on the gradient-sign attacks, 12.8%
on DeepFool). That is the expected outcome of training on a *fixed pool*: the
model learned the perturbations it was shown, and a recomputed gradient finds new
ones. Real robustness needs examples generated inside the training loop against
current weights (Madry et al.).

**The ensemble does the work, and not for the reason the paper suggests.** OR
holds 73–100% throughout — but only because a perturbation computed against one
member's gradients does not transfer to the other two. That is diversity, not
hardening. The weakest cell, FGSM against the hardened MLP at **73.36%**, means
26.6% of attacks evade the full EIDS with a single-model attack.

**The caveat that bounds all of it:** nobody here attacked the *ensemble*. A real
adaptive adversary optimises against all three gradients jointly, and the entire
73–100% column rests on them not having done so. That is the phase 8 experiment,
and the 100% figures should not be quoted without it.

Reported in `artifacts/reports/table7_eids_clean.{csv,md}`,
`table8_eids_robustness.csv`, `per_type_recall_eids.csv`, `eids_metrics.json`.

## Phase 7 — the pipeline end to end

```powershell
python scripts\07_pipeline.py
```

`validator → discriminator → EIDS`, short-circuiting on the first stage that stops
a flow. Per-stage columns are therefore *what each stage saw and stopped*, not
what it would stop alone. ~2 minutes.

**One correctness point governs the numbers.** Phase 5 drew its clean negatives
from `test.npz`, so measuring this pipeline on the full test split would grade the
discriminator on its own training data. The script rebuilds the phase-5 dataset
from the same seed, recovers its training fold, and evaluates on the 182,469 rows
that fold never saw. That is why the counts below are smaller than the test split.

### Table IX — end to end

| traffic | n | stopped % | by validator | by discriminator | by EIDS | allowed |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| clean benign | 167,040 | 1.159 | 0.952 | 0.000 | 0.207 | 98.841 |
| clean attack | 15,429 | 99.994 | 0.097 | 0.000 | 99.896 | 0.006 |
| all 12 adversarial sets | 1,484 each | **100.000** | **100.000** | 0.000 | 0.000 | 0.000 |

The validator catches every adversarial flow first, so **the discriminator and the
EIDS never see one**. Everything phases 5 and 6 built is, in the deployed ordering,
dead weight against these attacks — including the 90 minutes of adversarial
training.

### Table X — ablation

| stages | catch % | FPR % |
| --- | ---: | ---: |
| discriminator | 100.000 | **0.000** |
| eids | 99.983 | 0.219 |
| validator | 100.000 | 0.952 |
| discriminator + eids | 100.000 | 0.219 |
| validator + discriminator | 100.000 | 0.952 |
| validator + eids | 100.000 | 1.159 |
| **validator + discriminator + eids** | **100.000** | **1.159** |

| stage | catch lost if removed | FPR saved if removed |
| --- | ---: | ---: |
| validator | **+0.000 pp** | +0.941 pp |
| discriminator | **+0.000 pp** | +0.000 pp |
| eids | **+0.000 pp** | +0.207 pp |

**No stage contributes any catch the others do not already provide.** All three
independently stop ~100% of these adversarial flows, so the layering adds nothing
but false positives. The full three-stage pipeline drops **1.159%** of legitimate
traffic to achieve exactly what the discriminator alone achieves at **0.000%**.

### Why that is not "delete the validator"

The ablation is measured on the four attacks the discriminator was *trained on*.
Phase 5 already showed what happens outside that set: held-out DeepFool, **2.85%**.
The validator's rules are arithmetic and were mined from benign traffic only, so
they hold against an attack nobody anticipated; the forest does not.

So the redundancy is real but the conclusion is narrower than it looks. The
layering buys robustness to attack *novelty*, not to these attacks — and an
evaluation that only tests known attacks cannot see the difference. That is
precisely the gap the paper's own evaluation leaves open, and it is the strongest
thing this reproduction has to say about the framework.

The honest deployment reading: the discriminator is the cheapest stage that covers
known attacks at zero cost, the validator is insurance against unknown ones priced
at 0.95% of legitimate traffic, and the EIDS — in this ordering, on this data —
earns nothing it is not already owed as the NIDS.
